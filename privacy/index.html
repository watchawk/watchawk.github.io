Privacy policy

Mail Poll. Last updated 14 November 2026.

What Mail Poll accesses

When the owner of a Gmail account signs in and agrees, Mail Poll gets read-only access to that mailbox. It reads recent messages, including those in the Trash and Spam folders, to check them against a list of keywords and sender names. This is the only purpose.

What is stored and sent

For a message that matches, Mail Poll sends the sender, the subject line, the time it was received and the text of the message as an alert. Attachments are not included. For every message, matching or not, the sender, subject line and time received are kept in a log that the person running Mail Poll can view, so they can see what has arrived. The log is permanent: an entry is not removed when the message is deleted. The list also records whether each message is still in the mailbox, in Trash, in Spam, or has been deleted, and keeps its entry after the message is gone. The text of messages that do not match is never copied or sent anywhere.

Payment alerts

Some matching messages are payment alerts from a bank or payment app, such as a UPI or card payment. For these, a small record is also kept so payments can be tracked over time: the amount, the payee name or UPI ID shown in the alert, the bank or app, whether money was paid out or received, the mailbox address and the time. The record never includes the message text, account or card numbers, balances or transaction reference numbers. It is held on a private home server run by the person running Mail Poll, not on a public service.

Daily test message

To confirm that alerts still work, one short, clearly labelled test email may be sent each day to one of the connected mailboxes by the person running Mail Poll. It is recognised by its subject and sender, is not treated as a match, is not kept in the log, and its text is not read. It can be deleted.

Mail settings check

Mail Poll can also look at each connected mailbox's settings, at most twice a day, to see whether a filter has been set up that deletes mail or keeps it out of the inbox, or whether forwarding to another address is turned on. Either could stop alerts from seeing a message. This uses the same read-only access, and nothing in the mailbox is ever changed. What is kept is only a count of such filters, a fingerprint that lets a new one be recognised, and whether forwarding is on or off. What a filter matches and any forwarding address are not stored or sent anywhere. If a new filter of this kind or forwarding appears, the person running Mail Poll gets a short note on Telegram.

Payment text messages

With the phone owner's agreement, a payment text message from a bank or payment app (for example a UPI or card payment, sent or received) can be passed on from the phone to the person running Mail Poll. Only texts that mention an amount of money are passed on. Any one-time code, PIN or CVV in a text is removed, as far as it can be recognised, on the phone before it is sent, and removed again before anything is stored. The text goes through a relay on Cloudflare that holds it for seconds to minutes, and for at most 3 days if the home server is switched off, and then deletes it. What is kept is the same small payment record as for payment emails: the amount, the payee or UPI ID shown, the bank or app, whether money was paid out or received, and the time. The text itself is not kept, and the alert that is sent to the person running Mail Poll shows only those details. The phone owner can switch this off at any time by turning off the automation in the Shortcuts app.

Who receives it

The alert for a matching message is sent to the person who runs Mail Poll, through Telegram and through a private GitHub repository. These services only deliver and hold the alert, which includes the message text. To start a check promptly when mail arrives, Google Cloud Pub/Sub and Cloudflare relay a change notification. It contains only the mailbox address and a change counter, never any message content. The information is not sold, not used for advertising, and not shared with anyone else.

How long it is kept

Alerts stay in the private repository and in the Telegram chat until the person running Mail Poll deletes them. The mail log, which holds sender, subject, time and status only and never message text, is kept in the private repository until the person running Mail Poll deletes it. The payment record described above is kept until the person running Mail Poll deletes it. The status file used for the dashboard is kept for 7 days. Sign-in credentials are held as encrypted secrets in the private repository, and a copy is held on a private home server run by the person running Mail Poll, which carries out the frequent checks. That server is not reachable from the public internet.

Your choices

The account owner can remove Mail Poll's access at any time at myaccount.google.com/permissions. After that, Mail Poll can no longer read the mailbox. To ask for stored alerts to be deleted, email watchawk@proton.me.

Google user data

Mail Poll's use and transfer of information received from Google APIs follows the Google API Services User Data Policy, including the Limited Use requirements.
